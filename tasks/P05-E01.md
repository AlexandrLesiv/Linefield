## Outcome and boundaries

Owner retains CanvasKit and permits a higher web budget. Proposed first gate, requiring task
confirmation: validate pinned stock0.41.1 startup, heap observation and bounded-scene footprint
under WMP-C2's owner-approved320MiB owned-CPU operating target and separate96MiB graphics
allowance. Stock initial128MiB/max2GiB remain explicit; the256MiB CanvasKit operating share
is not a hard maximum. Owner clarified these as soft monitoring targets, not suspension
thresholds. Verify cache reclamation and handling of actual allocation/display failures;
preserve usable Rust RAM. Do not manufacture an actual-failure condition from a target crossing.
Present measured results before accepting integration; custom build is not a prerequisite.
Unobservable allocations or unsafe failure handling require concrete options for review.
Measure representative short/long paths, growth and reconstruction peaks to replace the
withdrawn128-stroke reservation with capacity-based admission. Exact Rust capacities and
observed CanvasKit heap capacity are distinct from estimated live-path allocation. Return
the concrete accounting/eviction proposal for review; no fixed stroke quota or invented exact
per-path meter. Resolve the corresponding scene/binding amendment before editing implementation.

Load the approved Rust/Wasm runtime and CanvasKit in the existing New drawing screen.
Create one empty in-memory Rust document/client; render a fixed-light empty surface and
exercise metrics/suspend, revision-consistent scene reads, navigation and disposal. Show
approved localized loading, not-saved and failure states. Do not accept pen input yet or
present this foundation as the usable drawing outcome; [P05-E02](P05-E02.md) supplies it.

Hard dependency: [S02-W01](S02-W01.md) integrated contract/design packet, exact owner
approvals and separate confirmation of this task. Implement only that reviewed subset.
