# P05-L01 — Create a saved drawing

**Status: prepared; blocked for production implementation.** Backlog priority 1, parent S02L/P05.
Owner approved the outcome and requested implementation preparation. This is a prospective
executable slice; it does not adopt an unsafe storage backend or approve unseen durable UI.

## Outcome

From the existing web gallery, create an automatically named blank drawing, open it, return to
the gallery and reopen the same identity/name after reload and browser restart. Show truthful
pending, confirmed, uncertain and failure states. Bounded listing and open are supporting
capabilities for creation/reopen, not an expansion to general library management.

Exclude rename (backlog 8), removal (9), real ink/history, import/export, native apps, cloud,
folders and migration of sample artwork. Existing sample cards remain prototype fixtures and
must not masquerade as durable user documents. Disposable settings cannot mutate stored fields.
Prototype Rename/Delete must not appear to persist changes to a real saved drawing.

message bodies, route IDs and concurrent/stale clients. Validate identity/version/capability,
bound work and allocations, preserve uncertain data, and avoid content/path logging. Document
concrete corruption, quota, eviction, worker-crash, duplicate-request and stale-authority outcomes.

checks source and actual evidence. Mark ready only when the entry gates are satisfied. Completion
requires passing applicable runtime acceptance and owner PR review/merge, followed by verified
integration. Missing evidence remains a gap. This document is preparation, not completed storage.
