# P05-R03 — Retained coverage and affected-region Undo rendering

Type: executable leaf under P05-E02. Status: proposed/conditional; not authorized.
Order: third web rendering task after R02 acceptance and separate scope/contract confirmation.
Plan: [Web rendering R2](../docs/interfaces/web-rendering-r2-proposal.md).

## Outcome and scope

Make pan request real offscreen geometry while the gesture is held, preserve safe coverage
through replacement and reuse unaffected artwork during Undo/Redo. Implement Rust conservative
chunk/stroke bounds, bounded contributor enumeration and bounded last-transition damage;
host prepared-geometry retention, a bounded 256 px raster tile cache and guard-region refresh
using the R01 repaint operation. Raster tiles are an explicit proposed amendment to the prior
vector-cache-only direction, requiring owner approval. No new brush/quality mode, persistence
or native code; tiles are disposable rendering derivatives, not canonical document storage.

Guard region starts at up to 25% each edge with up to 48 MiB additional surrounding tile pixels.
Separate tile allocations preserve the individual surface limits without forcing zero margin
at the maximum viewport. Lower memory can still reduce margin: label that degraded coverage,
not a passing zero-hole equivalent. Rust owns the raster grid, tile IDs/local projection,
actual union-of-tile coverage and pan transforms. No coordinate snapping or repeated resampling
of transformed images. Missing visible coverage precedes speculative margin work.

Undo repaints all surviving contributors in the changed area; Redo reuses valid prepared
geometry. Skipped/unrepresented content transitions return full damage. Full damage still
uses bounded operations. A stale render must never resurrect undone artwork or confuse a new
history branch with an old one of equal size. Eviction affects speed, not document/history.

designer, numerical/performance and fresh review. No new rendering algorithm outside R01.
