# Durable library: preparation complete, implementation blocked

The library will keep unnamed drawings without a filename prompt. Create, list, open and rename
must preserve identity and durable state. The existing gallery is a disposable UI prototype.

## Why implementation is blocked

The storage experiment found synthetic metadata damage could truncate a drawing database.
Proxy retirement also remains unproved. Healthy-case passes do not resolve these failure cases.
A non-destructive admission investigation and concrete storage contract review are still needed.

## What can proceed

The independent S02-P01 investigation can prepare evidence within its authorized synthetic scope.
The proposed durable empty-library implementation scope needs owner approval after its blockers
are resolved. This package does not authorize runtime persistence or choose a storage backend.

## Pilot conversion

S02L is a milestone, so it has no implementation branch or PR. Its future executable children each
own one branch and PR. The original milestone document retains the full policy extensions and
acceptance detail; this supplemental view maps its six named library scenarios. Planned native
scenarios are not counted as executed automated tests.
