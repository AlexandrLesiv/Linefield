Brief and limits

Understand Concepts generally, with particular depth on its size/opacity/smoothing controls, to inform later Linefield design. Target reference is Concepts for iPhone/iPad; Windows/Android differences are included only where explicitly documented. macOS remains Linefield's primary product target, with web implementation first. This packet does not alter the existing gallery, approved Pen/Select/navigation scope or the pending drawing proposal (repository reference). Smoothing, brush libraries, layers, multi-selection and other competitor features do not become Linefield requirements through this research. The existing macOS color-control direction remains.

Method: read public official manuals, release notes, tutorials, feature/pricing pages and support articles. No application/device access, sign-in, purchase, private upload or competitor asset copy. The lead separately owns physical-iPhone observation and its exact device/build/entitlement record. That session uses an iPhone 15 Pro Max through iPhone Mirroring, without Apple Pencil; it cannot establish squeeze behavior. Mirrored mouse actions are not direct finger or Pencil measurements. Public pages were available through web retrieval; a direct Node fetch failed DNS. The official video catalogue was readable but its walkthrough playlist fetch failed; no Concepts playback or transcript was inspected. The Apple follow-up used an official transcript, not motion measurement. Static images and descriptive image labels are not motion evidence.

Evidence labels below: D documented vendor claim; U unresolved by inspected sources; I inference/recommendation, never observed behavior. High confidence means clear source wording, not verified operation. Medium means legacy, ambiguous or conflicting documentation. No row is directly observed app behavior. Live manuals are unversioned; do not assume every section describes the latest installed build. Source dates and platforms below apply to their linked findings.

Ranked research recommendations, subject to design and owner review

  1. Investigate: compare tap-open and temporary hold-slide for approved width controls. The problem is fast adjustment without losing canvas context. Compare an anchored tray against a conventional native popover/slider. The tray may shorten repeated adjustment; hidden hold behavior costs discoverability and gesture testing. Keep visible, keyboard/AX operable entry and localized numeric values in the design comparison. Acceptance for a later approved slice: adjust width with each supported input, dismiss, and verify correct subsequent stroke plus no accidental canvas action. Host controls suit native focus/accessibility; this research neither selects rendering ownership nor changes the shared semantic contract. No persistence, latency or security improvement is inferred from the visual form.
  2. Investigate: make control scope visible before reusing controls for selected content. Concepts' documented selection restyling is useful context, but Linefield currently lacks that feature. Alternative is separate inspector presentation if later approved. Shared controls save space but risk changing the wrong target and add undo/state/AX announcement tests. Acceptance would distinguish future-pen settings from selected-stroke properties across select/deselect/undo. This is a future design question, not permission to add restyling.
  3. Adapt within existing scope: evaluate explicit navigation/tool entry independently of squeeze. Visible controls and reviewed keyboard access serve mouse, touch and non-squeeze styluses. Gestures can become optional accelerators after capability review. Alternative is gesture-first discovery, with greater accessibility/support cost. Observable acceptance is access to every approved action without special hardware while preserving native text input and browser context behavior. Designer/platform owners assess bindings; WEB-D02/08 remain planned.
  4. Defer: the rest of Concepts' feature breadth. Layers, brushes, precision guides, PDF, objects, accounts and sync explain Concepts workflows but create substantial semantic, persistence, accessibility, security and testing obligations. Keep their evidence as context; feature-specific research follows a future owner request. No parity target, new storage/network mechanism, benchmark or source-asset reuse is recommended.
