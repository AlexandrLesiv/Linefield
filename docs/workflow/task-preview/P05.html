P05 web

Status: owner-authorized live gallery prototype implemented in apps/web (decision 214); full Rust/Wasm editor and persistence remain planned/gated.

Host: apps/web. Technology: TypeScript + semantic HTML, Rust/Wasm and Skia CanvasKit.

Outcome: Browser editor with native browser semantics; no claim of AppKit or WinUI widgets.

Owner: Lead-assigned web implementer; ui_ux_designer owns platform interactions and native visual design per docs/design/roles.md.

Dependencies: reviewed portable contracts and approved implementation slices; macOS S08 acceptance is not a dependency. Decision 231 places web first because of the owner’s web experience, while macOS remains the primary product target and next implementation platform. iPhone/iPad follows macOS. S00–S02 portability/design review applies to web from the start; the sequence decision does not approve an unreviewed Wasm, storage or execution contract.

Before implementation: approve platform capabilities/non-goals, identified design states, typed boundary/resource ownership, storage/lifecycle/threading strategy, target devices and test/performance budgets. No custom command packets or duplicated editor state. Follow [platform plan](../docs/platforms.md).

Acceptance: shared semantic/document conformance; actual target build; native/browser E2E; accessibility and input/focus; failure/cancellation/recovery; bounded caches/logging; measured frame work and memory. Viewer targets enforce read-only capabilities. Missing hardware is a gap, not a pass. Lead assigns new platform-specific acceptance IDs mapped to executable tests before work starts.

Each assignment fixes base commit, owned paths, contract owner, tests/evidence and stopping condition. No incidental features or publication. Decision 214 additionally authorizes the browser design prototype, its manifests and tests.

SQLite portability checkpoint

Decision 29 selects native rusqlite; its documented sqlite-wasm-rs backend is a browser candidate,
not an accepted runtime. Before full web UI work, verify a reviewed worker/VFS arrangement with
create/edit/save/reload, native/browser snapshot exchange, migrations, quota exhaustion,
competing-tab locks, unavailable/private storage and interrupted saves. Default memory-only
storage must never be presented as persistent. Keep command/state/save policy shared in Rust;
report browser-specific durability/capabilities honestly. Browser journal mode and worker
ownership require review; macOS WAL/disk synchronization cannot be assumed to carry over.
These are planned checks, not implemented or executed evidence.
