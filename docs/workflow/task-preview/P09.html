P09 chromeos

Status: platform architecture/documentation planned from day one; no feature implementation.

Host: apps/chromeos. Technology: Android desktop route and/or browser route.

Outcome: Integration/acceptance folder; reuse apps/android and apps/web, not a third editor or assumed new OS SDK.

Owner: android_ui plus assigned web implementer; ui_ux_designer owns platform interactions and native visual design per docs/design/roles.md.

Dependencies: macOS S08 acceptance, reviewed portable contracts and explicit implementation direction; iPhone/iPad is the next platform priority. Portability review and design planning can happen during S00–S02.

Before implementation: approve platform capabilities/non-goals, identified design states, typed boundary/resource ownership, storage/lifecycle/threading strategy, target devices and test/performance budgets. No custom command packets or duplicated editor state. Follow [platform plan](../docs/platforms.md).

Acceptance: shared semantic/document conformance; actual target build; native/browser E2E; accessibility and input/focus; failure/cancellation/recovery; bounded caches/logging; measured frame work and memory. Viewer targets enforce read-only capabilities. Missing hardware is a gap, not a pass. Lead assigns new platform-specific acceptance IDs mapped to executable tests before work starts.

Each assignment fixes base commit, owned paths, contract owner, tests/evidence and stopping condition. No incidental features or publication. Current scaffold authorization permits documentation only.

Shared E2E adoption

Implement applicable scenarios from [shared E2E](../docs/testing/shared-e2e.md) with real native/browser actions. Reuse semantic fixtures/assertions and add platform focus/input/lifecycle/storage supplements. Declare capability exclusions; TV/Watch must pass VIEWER-001 and shared read-only conformance. P01 validates which small helpers actually warrant reuse before generalizing. Test the implemented typed adapter against [CT contracts](../docs/contracts.md); another host's results do not certify this port.

Tooling gate: select/verify the applicable language/platform tools and actual-host test lanes from docs/quality.md before implementation. Record supported pinned versions and runnable commands; planned tools are not installed checks.

Internationalization: map CT-09/INV-11/SU-20 to native resource/formatting/input APIs and applicable locale scenarios; preserve shared semantics and read-only capabilities. Require English (en) and Ukrainian (uk), selected from OS/per-app preferences at launch (browser preferences on web), with no in-app switch. Require both locale E2E lanes and reviewed translations; no automatic support claim. See ../docs/internationalization.md.

Before host implementation, review [navigation](../docs/navigation.md) and [motion](../docs/design/motion.md).
Specify native Back/focus/restoration, URL/link entry if approved, interruption/reduced motion
and capability-specific cases. Map [shared route/motion tests](../docs/testing/navigation-motion.md)
to actual host execution; a generic replay or static mockup does not certify this host.

Launch acceptance includes I18N-LAUNCH-002/I18N-UK-002 on this host, including viewer UI where applicable. See docs/testing/internationalization.md; no resources or execution evidence exist yet.
